# 题库生成与验收

## 何时进入哪个模式

| 用户说 | 模式 | 首步动作 |
|---|---|---|
| 出题 / 生成题库 / 批量命题 | A 生成 | 先读标准文件，确认配额与批次表，再写单篇 |
| 评审 / 这批题有什么问题 / 能不能用 | B 评审 | 先跑机器校验，再做 Pro/人工项逐条核对，最后出评审报告 |
| 改一下 / 修正后重新导入 / 把旧库升级 | C 修改 | 先读导出包，保留结构，逐处改，最后整包复校 |

## 铁律（违反即失败）

1. **一次一篇。** 绝不一次生成多篇；用户要求"一次全生成"时，说明硬凑的具体后果并给出分批表，由用户决定。
2. **先定标准再动笔。** 标准必须写清：词数、句长、Flesch 区间、空位数、选项数、字段白名单、枚举闭集（题材、语法标签、册次格式）。
3. **每篇写完立刻跑校验器；每批 0 阻断且 0 警告才前进。**
4. **语义字段不许为过校验而改。** 册次倒填是最典型的错误：校验被满足，语义被掏空。若必须改，先证明改的是"真实考点归属"。
5. **改正文必须同步改三处**：正文 → `evidence_sentence` → 解析里的引文。
6. **不得声称机器已验证 Pro 项。** 可解性、四选项同词类、唯一最佳、语篇连贯、阅读选项无歧义——这五项标 `待人工`。

## A 模式：生成

### A1 建批次表（先做，别边写边算）

```
总题数 = Σ(题型篇数 × 每篇题数)
完形 12×15 + 语法 12×10 + 阅读 40×4 + 七选五 8×5 = 500 题 / 72 篇
```

若用户给的总数与题型篇数算不出，先修算术，不要"写的时候再凑"。
每批控制在 27–46 题（单批过大必然质量下滑）。

### A2 单篇写作（每篇重复）

1. 选题材：从标准枚举里选未用满的；记录已用次数，单项 ≤6 篇。
2. 定参数：词数目标、句长目标、Flesch 目标、空位数量、近义辨析数量。
3. 写正文：优先"具体制度 + 具体数字 + 非学生主角"。
4. 挖空：先定 3–4 个近义辨析点，再补其余空。
5. 写解析：第一句依据 + 两个干扰项点名（用 A/B/C/D 字母 + 选项文字）+ 考点一句话。
6. 自检后落盘到 `batch-NN.json`（`bank-v1`，`name = 正式名#batch-0N`）。

### A3 单篇校验

```
python3 m26_validate.py <file.json>        # 退出码 0 通过 / 1 有阻断 / 2 不可解析
```

按错误码逐条修：
`ANSWER_WORD_APPEARS_IN_PASSAGE` → 换答案词或改正文；
`CITATION_NOT_FOUND` → 解析引文与正文不一致，同步；
`PLACEHOLDER_GRAMMAR_INVALID` → 语法篇必须单圈码 `①`，不是 `（①）`；
`GRAMMAR_TAGS_INVALID` / `GRAMMAR_CATEGORY_INVALID` → 用了闭集外的值；
`BOOK_TAG_INCOMPATIBLE` → 该考点不允许这个册次，改考点或改册次（先确认真实归属）。

### A4 合并

```
python3 m26_merge.py --name <正式名> --out <正式名>.json <12 个批次文件>
```

合并器必须：按 `passage_group_id` 去重、按实际重算 `target_size`/`composition`、合并后自动复校、题数与篇数达标才升 `m26-v1`。

### A5 交付前四项数据形态检查（标准通常没写，但必须查）

```python
# 答案位置分布
from collections import Counter
c = Counter(q['options'].index(q['answer']) for p in passages for q in p['questions'] if q['options'])
# 单点占比 >35% 即需确定性重排（种子取 passage_group_id + 题号），并同步改写解析字母
```

1. 答案位置分布（单字母 ≤35%）
2. 正确项是否为唯一最长选项（应接近随机 ~25%，明显偏高即偏置）
3. 跨篇 8-gram / 6-gram 重复（8-gram 必须为 0）
4. 题材、语法标签、册次格式是否全部落在枚举闭集内

## B 模式：评审

按顺序做，不要跳步：

1. **机器校验**：跑校验器，把阻断 / 警告 / 待人工分开列。
2. **数据形态**：上述四项。
3. **Pro 项逐条**：可解性（逐空代回，检查主谓、及物性、可数性、介词、时态语态）、四选项同词类、唯一最佳、语篇连贯、阅读选项无歧义。
4. **串篇检查**：解析里提到的场景/人物/细节是否与正文一致（"咖啡馆"出现在"维修俱乐部"篇里就是串篇）。
5. **引文抽查**：解析里所有标为"原文/正文"的英文引文，逐条在正文中搜。
6. **状态与命名**：生成文件不得带 `status`；修改包命名 `原名#revised-NN`。

报告写法：每条问题给「位置 + 原文 + 违反条款 + 后果 + 修法」，不要写"建议优化"。

**评审者不得同时是生成者。** 自评产出的是漂亮报告，不是质量。

## C 模式：修改

1. 读导出包，确认 `validation_profile: stored`、七选五篇级 `options` 完整。
2. 保留 `passage_group_id`；每处修改记录 before/after。
3. 改完的篇置 `validation_profile: m26`；建议整包置 `m26` 后重新验收。
4. 更新 `name`（`原名#revised-NN`）、`generated_at`、`target_size`、`composition`。
5. **整包**跑一遍机器校验，再跑四项数据形态检查。
6. 输出完整 JSON，不给 diff。

## 交付清单（缺一不可）

- [ ] 文件是严格 JSON，无 Markdown 围栏、无注释
- [ ] 顶层字段与标准完全一致（不多不少）
- [ ] `target_size` = 实际题数；`composition` = 实际篇数
- [ ] 机器校验 0 阻断
- [ ] 0 警告（警告数可以在批级容忍吗？本项目结论：**不可以**，攒到合并后会返工）
- [ ] 四项数据形态检查通过
- [ ] 待人工项数量如实报告，不冒充已验
- [ ] 逐篇通读一遍（读的人不是写的人）
- [ ] 成本按真实花费报告（含失败重试）

## 常见失败模式（按出现频率排序）

| 频次 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 高 | 完形词数够但 Flesch 偏高 | 补的词都是短句 | 换音节更密的同义词 / 合并句号 / 加多音节抽象名词 |
| 高 | `CITATION_NOT_FOUND` | 改正文没同步解析引文 | 建立"改正文必同步"的肌肉记忆，或让脚本自动比对 |
| 中 | 语法篇占位符报错 | 写成全角 `（①）` | 只写 `①` |
| 中 | 册次冲突 | 考点归属与册次不匹配 | 查考点允许册次表；完形/阅读/七选五只用全册可用三 tag |
| 中 | 解析未点名干扰项 | 写了"第二个选项"或"其余选项" | 用 `A 项 xxx` 格式 |
| 低 | 答案与原文连续重合 ≥5 词 | 阅读答案照抄句子 | 改写为同义转述 |
| 低 | 双解 | 两个近义词都能成立 | 不换词、改句子，给正确答案加一个排除性线索 |
