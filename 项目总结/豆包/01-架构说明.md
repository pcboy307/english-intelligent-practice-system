## 3. 题库数据模型

### 3.1 文件层（`bank-import-package.json`）

顶层**只允许 7 个字段**：

```json
{
  "format_version": "m26-v1",
  "name": "20261109_500",
  "target_size": 500,
  "difficulty_profile": "advanced",
  "generated_at": "2026-11-09T16:00:00+08:00",
  "composition": {"cloze": 12, "grammar_fill": 12, "reading": 40, "gap_fill": 8},
  "passages": []
}
```

- 不得出现 `bank_id` / `bank_tag` / `status` / `created_at` / `updated_at`（由导入器与数据库管理）。
- `target_size` 是实际题数，`composition` 是**实际篇数**。
- `format_version`：`bank-v1`（分批/普通/导出/局部修改包）、`m26-v1`（只给完整 72/500）。

### 3.2 语篇层

```json
{
  "validation_profile": "m26",
  "type": "reading",
  "passage_group_id": "M26-B11-READING-02",
  "topic": "历史遗产",
  "book_source": "选必二 U3",
  "difficulty": 4,
  "word_count": 418,
  "flesch_reading_ease": 50.64,
  "passage": "...",
  "questions": []
}
```

- `passage_group_id` 全文件唯一；`number` 每篇 1..n 连续。
- `word_count` / `flesch_reading_ease` 是说明字段，**后端从正文重算**，不信任自报值。
- 七选五额外带篇级 `options`（A–G 七句），每题 `options` 必须与篇级完全一致。

### 3.3 题目层（18 个允许字段）

```
number stem options answer explanation knowledge_points grammar_tags
book_source difficulty evidence_sentence reading_type grammar_category
cohesion_type context_clue clue_argument near_synonym_calibration
```

`answer` 存储形态按题型固定：完形 → 单词；语法 → 短语；阅读 → 完整选项文字；七选五 → 单字母。

### 3.4 数据库层

| 表 | 要点 |
|---|---|
| `banks` | `bank_id`(uuid)、`name`、`status`(generating/ready/active/archived)、`coverage_snapshot`(含 `switchable`) |
| `passages` | 关联 `bank_id`，存正文与语篇字段 |
| `questions` | 主键 **`(bank_id, id)`**（复合），非全局唯一 |
| `practice_sessions` | **表名不是 `sessions`**；阶段 0 时 1234 行 |
| `mistakes` / `coverage` | 错题与覆盖统计，按 `bank_id` 域隔离 |

外键 33 条。孤儿行排查见经验 `db-orphan-rows-constraint-gap`。

## 4. 校验体系：三层 + 双 profile

### 4.1 三层

| 层 | 位置 | 查什么 |
|---|---|---|
| L1 Schema | `contracts/schemas/bank-import-package.json` | 字段白名单、类型、必填、枚举 |
| L2 契约 | `contracts/m26-generation-params-v2.json`、`vocabulary-whitelist.json` | 词数区间、难度档、册次、词汇白名单 |
| L3 业务 | `backend/app/pg_store.py:24-54`、生成校验器 | 册次交集、配额合计、泄漏、引文存在性、解析质量 |

### 4.2 双 profile

| profile | 用途 | 执行内容 |
|---|---|---|
| `m26` | 新生成 | 全套门禁（含 M2.6 词数、Flesch、配额） |
| `m2` | 旧 M2 内容 | 历史词数区间（完形 170–220 等） |
| `stored` | 数据库导出 | 只做结构读取，不判内容 |

`format_version` 再分叉：`m26-v1` 要求全部篇为 `m26` 且执行 72/500 全库配额；`bank-v1` 不执行全库配额，只按各篇自身 profile 校验。

**这个双轨设计是必要的**：没有它，分批文件会被判「不完整全库」，旧库会被新规则拒收。

## 5. 关键不变量（改动时不可破）

1. 一个空位只有一个答案，答案在整篇正文出现次数为 0（含屈折，不含派生）。
2. 每篇阅读 4 题、题型互不相同、含 1 题 `paragraph_function`、高阶（非 `detail`）≥3。
3. `evidence_sentence` 必须是正文的**逐字符子串**；改正文必须同步改它。
4. `book_source` 只允许 `必修[1-3] U[1-5]` / `选必一 U[1-5]` / `选必二 U[1-5]` / `跨册综合` 四种写法；解析按 `startswith` 判册次。
5. 题级 `book_source` 的册次必须落在该题**全部** `grammar_tags` 允许册次的交集内；交集为空则不能出该双标签题。
6. 完形 / 阅读 / 七选五的 `grammar_tags` 只用全册可用的三个（`noun_clauses` / `tense_system` / `word_formation`），**禁止为过校验改 `book_source`**。
7. 语法填空每篇必须含五类：`non_finite_perfect_passive`、`preposition_plus_which`、`what_noun_clause`、`subjunctive`、`inversion`。
8. 占位符：完形 `(1)–(15)`、语法 `①–⑩`（**单圈码，不得写成全角括号**）、七选五 `(1)–(5)`。
9. 解析中文 ≥3 句，且点名两个干扰项。
10. 同题四个选项互不重复；正确项位置分布不得单点集中（建议单字母 ≤35%）。

## 6. 导入流程（现状 + 建议）

```
读文件 → L1 Schema → L2 契约 → L3 业务 → 写 banks(status=generating)
   → 写 passages/questions → 全库配额核对 → status=active
```

**问题**：最后一步自动置 `active`（`bank_transfer.py:1010`），与「换库须确认」冲突。

**建议改为**：

```
… → status=ready → 人工/评审批准 → status=active（旧 active 转 archived，switchable=false）
```

## 7. 组卷

- 输入：册次配额、难度配额、题型、可选排除项（错题、已做）。
- 抽题后校验 grammar tag 重复上限，避免一卷内同标签过于集中（Codex 验收记录：阅读场 29 题最大 tag 重复 3；七选五场 30 题最大 3）。
- 题量不足走 `fallback` 降级抽样（用户已接受不再修）。
