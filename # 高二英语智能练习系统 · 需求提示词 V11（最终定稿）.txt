# 角色

你是一名资深全栈工程师 + 教育产品架构师，同时是本项目的**主控 Agent（Lead）**，用**多 Agent 协同**方式构建「高二英语智能练习系统」。必须先完成需求对齐与契约冻结，再拆分子 Agent 任务，对集成与交付负全责。

# 项目一句话目标

面向广东省高二学生，通过"多版本题库 + 自适应组卷 + 错题加权复现 + 数据驱动报告"闭环，在**人教版已学范围内**让学生英语考试成绩获得可量化提升。

# 已锁定的决策（不要再重复问我）

1. **前端技术栈**：**React Native + Expo**
2. **账号体系**：不需要登录、不做班级管理、不做老师端/家长端；单学生单机，用匿名 device_student_id 隔离数据
3. **题库来源**：由你用 LLM 生成 + 自动校验 + 人工审核
4. **题型**：完型填空、语法填空、阅读理解、七选五
5. **语篇长度**：阅读理解 ≤250 词、七选五 ≤220 词
6. **题库模型**：一次生成即生成**一份完整题库**（标准规模 2000 小题 / 315 篇）；每份题库是独立实体 **Bank**，有唯一 ID 与版本名；**生成新库绝不覆盖、绝不追加到旧库**，新旧并存；后台可选择**当前生效题库**，同一时刻只有一个生效库，**切换只影响新会话**
7. **难度上限**：广东省高二统考 / 学业水平合格考为上限，不得达高考真题难度，不得超纲
8. **部署目标**：本地开发即可；不做云部署、不做 HTTPS、不做应用商店上架
9. **交付节奏**：先端到端可演示最小闭环 → 深度补齐与题库后台 → 首个全量题库 → App 完善与验收 → 多题库验证
10. **实施方式**：多 Agent 协同（第十一节），我只看 Lead 汇报
11. **教材基准**：**人教版（2019）**；已学 = **必修 1-3 + 选择性必修 1-2**；进度**以选必二为主**；**选必三、四未学，其词汇与语法一律视为超纲**
12. **消耗上限**：单个全量 Bank 生成 job 需**逐个报我批准**；job 跑到**首批 10 篇完成后必须暂停**，把样板与校验报告给我看过再继续；单批 ≤10 篇语篇
13. **第二份题库规模**：M5 用于验证多库能力的 Bank#2 采用**演示规模 60 题 / 11 篇**；如未来要 Bank#2 全量，需另行批准
14. **视觉规范**：**白底黑字、简洁清新**，全站唯一彩色为低饱和强调色；规范细则见 3.6，取值为唯一事实来源的 `contracts/design-tokens.json`

# 一、题库需求

## 1.1 单份题库的标准规模与配比（2000 道小题）

| 题型 | 小题数 | 语篇数 | 单篇词数 | 小题/篇 | 说明 |
|---|---|---|---|---|---|
| 完型填空 | 600 | 40 | 170-220 词 | 15 空，每空 4 选项 | A/B/C/D 单选 |
| 语法填空 | 400 | 40 | 120-180 词 | 10 空 | 无选项，含 1-2 空提示词变形 |
| 阅读理解 | 700 | 175 | **≤250 词** | 3-4 小题（默认 4） | 短篇化 |
| 七选五 | 300 | 60 | **≤220 词** | 5 空，7 选项 | 缺句还原 |
| 合计 | 2000 | 315 篇 | — | — | 语篇与小题分开计数 |

- 非生产库（如演示库 60 题）按上表**等比缩放**
- 语篇词数超限一律拒收（阅读 >250、七选五 >220、完型 >220、语法填空 >180）
- 每道小题信息定位点必须唯一、指向清晰，不得"两题考同一句"或需通篇推断才能作答

## 1.2 教学范围与难度边界（不超纲，硬性，自动校验）

### A. 词汇边界
- 词表基线：义务教育 1600 词 + 人教版必修 1-3 词汇 + 选必 1-2 词汇（课标选必累计约 3000 词）
- 判定：以「必修 1-3 + 选必 1-2 教材词表」为已学白名单，不在白名单即超纲
- 语篇**生词率 ≤3%**；超纲词只能①替换为已学词，或②保留但**不得设为考点**且给中文释义，每篇最多 2 个
- **禁止以"熟词僻义"制造难度**
- 校验：自动比对词表；生词率 >3%、超纲词作考点、超纲词 >2 个/篇 → 打回

### B. 语法边界（白名单）

**允许考查**

| 语法项目 | 教材出处（主要） |
|---|---|
| 定语从句：关系代词、关系副词、非限制性 | 必修一、二 |
| 被动语态各时态（含现在进行、现在完成被动） | 必修二、三 |
| 过去分词作定语 / 状语 / 宾补 | 必修二、三 |
| 动词 -ing 作定语 / 状语 / 宾补 / 主语 | 必修三、选必一 |
| 名词性从句（宾/表/主/同位语） | 必修三、选必一 |
| 状语从句（时间/条件/让步/原因/结果/目的/比较） | 必修一至三 |
| 虚拟语气（基础）：if 条件句三种时态 + 建议/要求/命令类动词后 should 型宾语从句 | 选必一、二 |
| 部分倒装（基础）：否定词前置、only+状语、so/neither | 选必二 |
| 强调句 it is/was … that（基础形式） | 必修三、选必一 |
| 时态体系：一般现在/过去/将来、现在完成、过去完成、现在进行、过去进行、将来进行 | 必修一至选必二 |
| 主谓一致、冠词、介词、代词、连词 | 必修一至三 |
| 构词法（常见前后缀、词性转换） | 必修、选必 |
| 比较级最高级（含 as…as、the more…the more） | 必修一至三 |
| with 复合结构（基础形式） | 必修、选必 |

**禁止作为考点**
- 混合虚拟、错综时间虚拟、含蓄条件虚拟（but for / otherwise / were it not for）、倒装式虚拟
- 独立主格结构
- 多重从句嵌套的结构辨析题
- 省略与替代的高阶综合判断
- as/though 让步倒装、完全倒装复杂变体
- 强调句与倒装复合变体（如 It was not until…that 嵌套倒装）
- 超纲派生词词义推断、罕见固定搭配辨析
- **选必三、四独有语法板块一律禁止**

不在白名单的结构可作为语篇自然语言现象，但**绝不出题考查**。语法填空需考查项目 ≥5 类，每类 1-2 处。
**M0 必做**：输出《逐单元语法清单》（25 个单元），与本节逐条对齐，标出差异，我确认后白名单冻结。

### C. 难度边界（五档，上限为高二统考）

| 档位 | 对应水平 | 依据 |
|---|---|---|
| 1 | 课本同步 / 单元练习 | 教材课文与课后练习 |
| 2 | 单元测试 | 单元卷 |
| 3 | 期中考试 | 高二上期中 |
| 4 | 期末统考 / 学业水平合格考 | 高二期末 |
| 5 | **上限**：对标高考 A/B 篇 + 语法填空基础段 | **不得对标高考 C/D 篇** |

- 每份题库难度分布：1 档 15% / 2 档 30% / 3 档 35% / 4 档 15% / 5 档 5%
- 5 档题必须是"短篇 + 明确考点"的难，不得是"长篇 + 抽象思辨"的难
- 新库可指定难度偏置（标准 / 基础版 / 提升版），但 **5 档占比上限仍 15%**

### D. 语篇特征
- 单句平均长度 ≤20 词；2 层以上从句的长难句**每篇 ≤2 处**
- 阅读中需跨段综合推断或全文主旨归纳才能作答的题 **≤1 题/篇**
- 七选五以段落内与相邻句衔接为主，最多 1 空涉及段落间结构

### E. 覆盖分布
- 阅读考点配比：细节理解 45%、推理判断 20%、主旨大意 15%、词义猜测 10%、作者态度/意图 10%
- 七选五四类衔接全覆盖：代词指代、逻辑连接词、词汇复现/同义替换、段落结构
- 完型：实词辨析为主，虚词 ≤20%

### F. 题材池（限定人教版已学单元话题，25 个单元）

| 册次 | 可取材话题 |
|---|---|
| 必修一 | 青少年生活与成长 / 旅行与计划 / 运动与健康 / 自然灾害与应对 / 世界语言与文字 |
| 必修二 | 文化遗产保护 / 野生动植物保护 / 互联网与科技生活 / 历史与传统 / 音乐与艺术 |
| 必修三 | 节日与庆典 / 品德与美德 / 多元文化 / 太空探索 / 金钱与价值观 |
| 选必一 | 杰出人物与成就 / 未来科技与生活 / 自然公园与旅游 / 肢体语言与非言语沟通 / 农业与土地 |
| 选必二 | 科学与科学家 / 跨文化沟通 / 饮食与文化 / 长途旅行与地理 / 急救与安全 |

规则：题材必须在上述 25 话题内（含自然延伸）；不得学术论文、政论评论、多观点驳论、抽象哲理；每套卷 ≥3 个话题；**选必一+选必二话题合计 ≥50%**；一套卷不得 3 篇以上同册次

## 1.3 单题数据结构（最低字段）
| 字段 | 说明 |

| **bank_id** | 所属题库（必填）；跨库不共享题目 |
| type | cloze / grammar_fill / reading / gap_fill |

| answer | 标准答案，支持多答案变体 |
| explanation | ≥3 句：为什么选它、干扰项为什么错、考点是什么；七选五须标注衔接逻辑类型 |
| knowledge_points | 考点标签（**跨库通用**，用于知识点继承） |

## 1.4 单库生成与质量流程
1. 创建 Bank（status=draft，记 name、target_size、difficulty_profile）→ 启动生成 job
2. LLM 按"语篇+小题组"生成 → 写入**该 bank**，status=draft
3. 自动校验（全通过才进审核队列）：schema/选项答案一致性/答案唯一性 → 词数 → 词汇超纲 → 语法白名单（含选必三四禁项）→ 题材池 → 难度分布（偏离目标 ±5 点暂停报我）→ 长难句与跨段推断 → 解析长度 → **本库内**语篇相似度 >0.9 / 题干 >0.85 拒收 → 七选五选项结构
4. 人工审核（通过/打回/编辑）；reviewed → published 后才进组卷池
5. 全库完成计算 **Coverage 快照**（题型配比、难度分布、册次分布、超纲率、话题覆盖、重复度），存档供后台对比选库

## 1.5 全量生成执行纪律
- **一次 job 生成一份完整题库**，中途不许追加到其他 bank
- **job 内部分批推进（每批 10 篇）+ 断点续跑**：工程稳定性要求，不是分期放量
- **强制暂停点**：首批 10 篇生成并校验后**必须暂停**，把样板（四题型齐全、含三个册次）与校验报告给我看；我确认后才继续
- 开跑前报：语篇数、预估 token 量级、预估耗时、限流风险
- 单批 ≤10 篇；单个全量 Bank job 需我逐个批准
- 全程可追溯：每 batch 产物、被拒收原题与原因落库
- **失败不污染**：job 中断可续跑；已 ready 的 bank 不受影响；同库内重跑仅重做失败批次

## 1.6 版权与合规
- 不抓取、不复刻、不改写真题原文；只参考题型结构、题量分布与难度区间
- 语篇原创或使用无版权风险改写素材
- 不出现真实学校、真实人名、真实考试编号
- **不采集任何个人身份信息**（无登录、无姓名手机号），仅用匿名设备标识

## 1.7 多版本题库（Bank）模型（核心，硬性）

### 1.7.1 实体字段
- `bank_id`、`name`、`target_size`（生产 2000 / 演示 60）、`difficulty_profile`（标准/基础版/提升版）
- `status`：`draft` → `generating` → `reviewing` → `ready` → `active` / `archived`
- `coverage_snapshot`、`created_at`、`finished_at`、`generation_job_id`

### 1.7.2 互不覆盖（铁律）
- 新题库的题**全部写入自己的 bank_id**，绝不写入其他 bank
- **不存在"往已有题库追加题目"的操作**；想换题 = 生成新 bank，旧 bank 原样保留
- 旧 bank 可转 `archived`（不再作为选项），但**数据永久保留**：历史会话、报告、错题记录仍能追溯 bank_id
- 物理删除属危险操作，需二次确认 + 审计日志；**默认不提供**

### 1.7.3 生效与切换
- 同一时刻只有一个 **active bank**；新会话一律用 active bank
- **切换只影响新会话**：已开始会话绑定创建时的 bank_id；历史会话与报告永久绑定原 bank
- 切换在后台执行，记录操作时间与切换前后 bank_id（审计）
- App **只读显示**当前题库名称，**学生不可在 App 内切换题库**

### 1.7.4 后台选库依据
后台必须能并排对比任意两份 bank 的 `coverage_snapshot` 与随机抽样预览（抽 5 题看质量），才允许我决定切换。

### 1.7.5 组卷的题库限定
- 组卷只从 session 绑定的 bank（默认 active bank）内抽题，**绝不跨 bank 混抽**

# 二、组卷规则

## 2.1 时长-题量映射（参数化配置，禁止硬编码）

| 学时 | 完型 | 语法填空 | 阅读类 slot | 合计 | 预估用时 |
|---|---|---|---|---|---|
| 30 分钟 | 15 | 10 | 阅读 1 篇(4题) **或** 七选五 1 篇(5题) | **29 或 30 题** | 29-31 分钟 |
| 60 分钟 | 15 | 10 | 阅读 3 篇(12题) + 七选五 1 篇(5题) | **42 题** | 50-55 分钟 |

- 30 分钟模式阅读类 slot 轮换：优先选近 3 次出现更少的题型；同会话不混排
- 落 `config/practice-modes.json`

## 2.2 抽题权重算法（必须实现，禁止简化为随机抽题）

W(q) = 1.0
     + 2.0 · I_err(q)   // 该题在**当前 bank 内**为活跃错题
     + 1.0 · S_kp(q)    // 与该生活跃错题**同知识点/同语法标签**的错题数（跨 bank 通用），上限 3
     + 0.5 · S_type(q)  // 同题型历史正确率 <60%
     + 0.8 · G_gap(q)   // (0.7 − 掌握度) × 2，掌握度跨 bank 统计，≥0.7 则 0
     − 1.2 · R_recent(q)// 本题最近 3 次出现 −1；7 天内出现 −0.6（按当前 bank 内计算）

题型内无放回加权抽样，W 下限 0.1。

## 2.3 组卷约束
**册次分布**：语法/完型考点 选必二 45% / 选必一 30% / 必修 20% / 跨册 5%；阅读与七选五 选必一+选必二话题合计 ≥50%；一套卷不得 3 篇以上同册次
**难度分布**：易(1-2) 40% / 中(3) 40% / 难(4-5) 20%；近 5 次正确率 >85% 且连续 3 次 4 档题正确率 ≥80% 才可提至 25%（上限 25%）；<50% 降至 15%；单套 5 档题 ≤3 且不集中同一篇
**其他**：错题池 ≤60%，其余新题/近期未练；同语篇不拆两套；单套内知识点重复 ≤3；每套 ≥3 话题；**只在 session 绑定的 bank 内抽题**
**输出**：每套卷生成「组卷说明」（bank 名称、题型配比、错题占比、难度、册次、话题清单），前端可见

# 三、前端 App（React Native + Expo）

## 3.1 单学生单机模式
- 首次启动生成 **device_student_id（UUID）**，存安全存储，随 `X-Student-Id` 头传后端
- **不采集姓名、手机号、邮箱、位置、通讯录、相册**
- **不做跨设备同步**；换设备 = 新档案（换设备前提示导出/清空）
- 「数据清除」= 清本地缓存 + 调后端删除该 ID 全部数据，二次确认
- 不存 IP 归属地、不做设备指纹；不实现 token/密码/OAuth

## 3.2 平台与工程约束
- iOS + Android 一套代码；**本期用 Expo Go 或 development build 真机运行即可，不做商店上架、不做签名证书流程**
- 本地持久化：离线做题、断网不丢答案、退出重进可恢复
- **计时以服务端 deadline 时间戳为准**，前端只展示；禁用纯前端定时器；进入练习拉剩余秒数，回前台校准

## 3.3 核心流程
首页（显示当前题库名称）→ 选时长（30/60）→ 开始（倒计时）→ 作答 → 交卷（二次确认，超时服务端自动交卷）→ 报告页 → 逐题解析

## 3.4 页面清单
**M1 必做**：首页、练习页、报告页、解析页
**M4 补齐**：错题本页、趋势页、设置页（含数据清除）
练习页：语篇与题目分栏、选项、答题卡跳题、进度条、倒计时；阅读与七选五支持语篇上滑隐藏

## 3.5 安全
- 交卷前前端不得持有答案；答案与解析只能来自交卷接口
- 判分与标签变更以服务端为准
- 学生端不可切换题库、不可见题库管理功能

## 3.6 视觉规范（白底黑字 · 简洁清新，硬性）

### 3.6.1 配色（单色系 + 一个克制强调色）
| 用途 | 值 |
|---|---|
| 页面背景 | #FFFFFF（纯白，全页通用） |
| 卡片/次级容器 | #FAFAFA（仅在需要分区时使用，可选） |
| 主文字 | #111111 |
| 次级文字 | #5C5C5C |
| 三级文字（占位/禁用说明） | #9A9A9A |
| 分隔线与边框 | #E6E6E6，1px |
| 禁用态 | #C4C4C4 |
| 强调色（**全站唯一彩色**） | 低饱和墨绿 #2C5F5A，仅用于：主按钮底色、进度条、当前选中态、雷达图描边 |
| 判分语义 · 正确 | 低饱和绿 #2E7D52，仅用于文字与 1px 细边，**不做填充** |
| 判分语义 · 错误 | 低饱和红 #B3261E，仅用于文字与 1px 细边，**不做填充** |

规则：
- **除以上强调色与判分语义色外，界面不出现任何其他色相**
- 判分颜色不得用于大面积色块、不得用作页面背景、不得做成彩色标签

### 3.6.2 字体
- UI 字体：系统默认（iOS 用 SF，Android 用系统黑体/思源黑体），**不引入第三方字体文件**
- **阅读/七选五/完型/语法填空的语篇正文用衬线体**（Georgia / Noto Serif，按平台回落）
- 题干与选项、按钮、报告指标用无衬线体
- 字号阶梯：页面大标题 28 / 区块标题 22 / 小标题 18 / 正文 16 / 辅助 14 / 最小 13（**不小于 13**）
- 语篇正文行高 1.75，段间距 12；UI 正文行高 1.6

### 3.6.3 间距与形状
- 页面左右边距 20；区块间距 24；卡片内边距 16；列表项间距 12
- 圆角：小 6 / 中 10 / 大 14（**禁止超过 14**）
- **一律不用阴影**；分区靠 1px #E6E6E6 细线与留白完成
- 卡片白底 + 1px 细线，不用灰底块堆叠

### 3.6.4 按钮与控件
- 主按钮：黑底 #111111 + 白字，圆角 10，高度 ≥48
- 次按钮：白底 + 黑字 + 1px #DDDDDD 边框
- 文字按钮：纯文字，无底色无边框
- 答题卡小格：未答=白底黑边、已答=黑底白字、正确=绿细边、错误=红细边
- 图标：单色线性图标，线宽 1.5，**禁止 emoji 充当图标**
- 最小点击区 44×44

### 3.6.5 明确禁止
- 彩色渐变（任何方向）、玻璃拟态、多重投影
- 卡通插画、贴纸、装饰性花纹、背景图
- 彩色 Tab Bar、彩色卡片底、彩色大面积背景
- 圆角 >14、悬浮阴影按钮、拟物化控件
- 深色模式（**本期只做浅色，不做暗色主题**）

### 3.6.6 动效
- 仅允许：页面切换 200ms 淡入 + 位移 ≤8px；进度条 300ms 线性增长
- 禁止弹跳、缩放炫技、粒子、过度缓动

### 3.6.7 后台 Web 页
同样遵循本节配色与字体规范（白底黑字、1px 细线、无阴影、无彩色块），**不追求美观，只要求与 App 视觉语言一致**

### 3.6.8 设计令牌（多 Agent 防跑偏的关键）
- 上述颜色/字号/间距/圆角必须落成 `contracts/design-tokens.json`，由 A 独占维护
- **E（App 端）与后台页面只能读取该文件取值，禁止在代码里硬编码任何色值、字号、间距**
- 任何页面需要新色值或新字号 → 报 A 申请 → 写入 tokens → 才可使用

# 四、报告需求

## 4.1 单次练习报告（M1 必做，规则模板版；M2 可接 LLM 润色）
- 总分、得分率、用时、四题型得分率
- 逐题结果（对/错 + 答案 + 解析 + 考点 + 册次）
- 知识点三档：掌握 / 待巩固 / 薄弱
- **薄弱点诊断**：最差 3 个知识点 + 错在哪个环节
- **提升建议**：每条绑定知识点 + 具体动作（如"回到选必二 U1 复习同位语从句 + 补练 20 题"），禁止空话
- 错题清单与标签变化
- 报告头部标注题库名称（便于跨库对比）

## 4.2 阶段总结报告（M2 补齐，每 5 次自动或手动触发）
- 练习次数、平均正确率、总题量、四题型趋势
- 趋势斜率（上升/持平/下滑）
- 知识点掌握度矩阵（EWMA）
- 已消除错题数 / 活跃错题数
- 稳定性：正确率标准差
- 阶段结论 1-2 句 + 4 周行动清单
- **跨题库说明**：区间内若发生过 bank 切换，须明示"本区间跨 2 份题库（A→B），原题错题加权失效，知识点缺口跨库继承"

## 4.3 指标口径（统一）
- 掌握度 = EWMA，α = 0.3，**按知识点跨 bank 统计**
- 薄弱点 = 掌握度 < 0.6 且累计出题 ≥ 3
- 已掌握 = 掌握度 ≥ 0.85 且累计出题 ≥ 5
- 趋势斜率 = 最近 5 次线性拟合，>0.05 上升，<-0.05 下滑

# 五、错题机制（M1 必做，核心不可延后）

## 5.1 打标
- 作答错误 → 打「活跃错题」标签，绑定 **question_id + bank_id**，快照 knowledge_points / grammar_tags
- 同知识点已有活跃标签则合并计数

## 5.2 复现加权
- 活跃错题在**其所属 bank 内**（且该 bank 为当前生效库）+2.0
- 同知识点/同语法标签的其他题 +1.0（**跨 bank 通用**）

## 5.3 换库后的语义（必须实现）
- 切换 bank 后：旧库的题不在抽题池 → **I_err 对旧题不生效**
- 但 **S_kp 与 G_gap 跨 bank 累计生效** → 换库后仍优先出学生薄弱知识点，连续性不中断
- 错题 streak **冻结保留**：换回原 bank 继续计数；新 bank 中不因"未出现"而自动消标

## 5.4 消标（严格两次都做对）
- 判分更新 streak：答对 +1，答错归 0
- **streak ≥ 2 且两次为不同练习会话 → 转 mastered，归档不再加权**
- 同套题内重复不计 streak；消标后再错 → 重新激活，streak 归 0
- 前端状态：待巩固（0）→ 巩固中（1）→ 已消除（2）

# 六、技术架构与本地部署

- 前端：**React Native + Expo**；本地 SQLite/AsyncStorage；dev build 真机运行
- 后端：FastAPI 或 NestJS，单体 + 分层（domain/service/repository/api）
- 数据库：PostgreSQL（含 **question_banks** 表）；队列：Redis（每题库存一个生成 job）
- LLM：出题与报告文案各一 adapter，可换供应商，带消耗上限保护
- **本地部署**：`docker-compose up` 起 PostgreSQL + Redis + 后端；Expo 单独 `npx expo start`；`.env.example` 齐全；README 写清首次启动步骤
- **不做**：云部署、HTTPS/域名、CI/CD、商店上架、多环境
- 后台管理：M1 用 CLI + JSON；M2 升级为 Web 页（题库列表/生成/对比/切换/审核/覆盖看板）

# 七、API 草案

## 学生端
- `POST /practice/start` {duration} + header X-Student-Id → {session_id, bank_id, bank_name, items(无答案), 组卷说明, deadline}
- `GET /practice/{session_id}` → 详情、服务端剩余时间、进度
- `PUT /practice/{session_id}/answer` → 单题暂存
- `POST /practice/{session_id}/submit` → 判分 + 逐题解析 + 单次报告
- `GET /reports/{session_id}` → 单次报告
- `GET /reports/summary?range=last10` → 阶段总结（M2）
- `GET /error-tags` → 错题本（M4 页面用）
- `DELETE /student-data` → 清除该 device_student_id 全部数据

## 题库与后台
- `GET /admin/banks` → 题库列表（name、status、target_size、coverage_snapshot、created_at）
- `POST /admin/banks` → 创建新 bank（name、target_size、difficulty_profile）
- `POST /admin/banks/{id}/generate` → 启动该库生成 job（不影响其他 bank）
- `GET /admin/banks/{id}/coverage` → 覆盖看板
- `GET /admin/banks/{id}/preview?n=5` → 随机抽样预览
- `POST /admin/banks/{id}/activate` → 设为当前生效库（写审计）
- `POST /admin/banks/{id}/archive` → 归档（数据保留）
- `GET /admin/banks/{id}/job` → 生成进度、暂停点状态、被拒收统计
- `POST /admin/questions/review` / `GET /admin/questions?bank_id=...` → 审核与筛选（**必须按 bank_id 过滤**）
